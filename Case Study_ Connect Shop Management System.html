The Problem

A shop selling phones, computers and accessories, and also doing repairs and cash transfers, needed to know at any moment: what's in stock, what sold today, what each repair earned, and which employee handled what.

The brief was a simple system that runs in the browser with no server and no subscriptions, that the staff can use from day one, and that works with the barcode scanner already at the counter.

My Role

I built the whole project myself: understanding how the shop works, designing the interface, designing the data model, and writing both the front end and the back end.

What I Built

Barcode Selling
Scan from any screen and the system jumps to the product and sells it. An unknown code opens a quick-add form with the code already filled in.
Repairs
Each ticket records the device, the fault, the customer, the parts cost and the labor margin, so the profit on every repair is clear.
Accessories & Devices
Categories and device types can be added freely. Every item has a code, wholesale price and profit margin, and stock drops with each sale.
Cash Transfers
Every transfer is logged with the customer, the amount and the employee who handled it.
Inventory
One screen to review, add and edit all stock, with codes generated automatically when none is given.
Accounting & Staff
Revenue, cost and profit across repairs, accessories and devices, with daily and periodic views. Staff accounts are manager-only.

Challenges and How I Solved Them

SpeedA Google Sheets backend is slow by nature

I cached the data in the browser, prefetched the main lists right after login, and moved saving to the background: the form closes immediately and a small message at the bottom confirms the data was updated. Moving between sections feels almost instant.

HardwareTelling a barcode scanner from a person typing

Scanners type much faster than people. I listen for fast keystroke bursts ending in Enter, so a scan works from any screen without clicking into a field, while normal typing in forms is left alone.

Unique codesItems without a barcode still need an identity

When no code is entered, the backend generates a six-digit one and checks it against both accessories and devices, so two products never share a code.

GrowthThe schema keeps changing as the shop does

Setup creates every sheet in one run, and a header check adds any missing column automatically, so new fields can ship without breaking existing data.

Visual Identity

A dark charcoal interface with copper accents for a professional, distinctive look. The whole layout is right-to-left in the Tajawal typeface, and the sidebar collapses to icons on small screens.

The Result

  • The shop runs on one system instead of scattered notebooks: repairs, sales, stock, cash transfers and accounting.
  • Barcode selling saves the cashier time, and every sale is tied to an employee.
  • The owner sees cost and profit on every transaction, with no manual calculations.
  • Running cost is close to zero, because everything runs on a Google account.
